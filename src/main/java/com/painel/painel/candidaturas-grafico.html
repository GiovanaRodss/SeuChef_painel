Melhoria: adicionar gráfico analítico na página de candidaturas

Documento visual para apresentar a alteração necessária na página Operacional > Candidatura. A proposta é adicionar um gráfico que compare, por mês, a quantidade de vagas publicadas, o total de candidaturas e a média de candidatos por vaga.

Os valores usados nesta prévia são dados de exemplo da referência enviada. Na versão real, todos os dados devem vir da base do painel e respeitar os filtros aplicados na página.
Anotação da melhoria

Adicionar gráfico de candidaturas por mês

Prioridade: Média Status: Pendente Área: Operacional Página: /admin/reports/applications-by-position
Problema atual A página de candidaturas mostra os filtros, totais e a lista operacional, mas não apresenta uma visão visual clara da relação entre vagas publicadas, candidaturas recebidas e média de candidatos por vaga.
Como deve funcionar Adicionar um gráfico combinado com barras para quantidade de vagas publicadas, linha para candidaturas e linha para média de candidatos por vaga.
Ajuste necessário Criar uma seção analítica na página Operacional > Candidatura, usando os dados agrupados por mês. O gráfico precisa mostrar a performance de candidaturas em relação ao volume de vagas publicadas.
Regras de cálculo

Como o gráfico deve ser calculado

O gráfico deve usar os dados de vagas publicadas e candidaturas recebidas, agrupados por mês.

Qtd vagas 2026: Total de vagas publicadas no mês. Candidaturas: Total de candidaturas recebidas no mês. Média candidatos por vaga: Total de candidaturas do mês / Total de vagas publicadas no mês.

A média deve ser exibida como número inteiro ou com uma casa decimal, conforme padrão definido no painel.

Requisito técnico

Dados dinâmicos do gráfico de candidaturas

O gráfico da página Operacional > Candidatura precisa ser alimentado com dados reais da base. Os valores não devem ficar fixos no HTML ou no JavaScript.

GET/API — Buscar dados iniciais Ao carregar a página, o front-end deve fazer uma requisição para buscar os dados reais da base e montar o gráfico inicial. A API deve retornar os dados já agrupados por mês.
Envio de filtros — Atualizar dados do gráfico Quando o usuário aplicar filtros na página, como data inicial, data final, cargo/posição, empresa, cidade ou nome do candidato, o front-end deve enviar esses filtros para a API para recalcular os dados.
Retorno esperado da API A API deve retornar os valores já tratados para o gráfico: quantidade de vagas, quantidade de candidaturas e média de candidatos por vaga. O front-end deve apenas receber os dados, montar os labels e atualizar a visualização.
Não deixar valores fixos Os arrays usados neste HTML são apenas exemplos visuais. Na implementação final, todos os valores precisam vir da base de dados do painel.
Fluxo esperado: 1. Usuário acessa Operacional > Candidatura. 2. Front-end faz GET/API para buscar os dados iniciais do gráfico. 3. API consulta a base e retorna os dados agrupados por mês. 4. Front-end monta o gráfico com os dados retornados. 5. Usuário aplica filtros na tela. 6. Front-end envia os filtros para a API. 7. API retorna os dados recalculados. 8. Front-end atualiza o gráfico.
Critério de aceite

Quando considerar essa melhoria concluída

  • A página Operacional > Candidatura passa a exibir o gráfico analítico.
  • O gráfico mostra quantidade de vagas publicadas por mês.
  • O gráfico mostra total de candidaturas por mês.
  • O gráfico mostra média de candidatos por vaga por mês.
  • Os dados são agrupados corretamente por mês.
  • Os dados são puxados da base por API/GET ou endpoint equivalente.
  • Os filtros aplicados na tela atualizam o gráfico.
  • Os valores não ficam fixos no front-end.
  • Os números batem com a base real de candidaturas e vagas.
